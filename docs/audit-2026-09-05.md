# Studio stability audit — 5 September 2026

Scope: application source, pinned Containerization 0.43.0 implementation, configuration parser, WebKit integration, packaging/CI, isolated regression tests, and a disposable-VM smoke test. The user's live containers, private volumes, and running app bundle were not modified. No release or version change was made.

The findings below record the original audit. The remediation status here takes precedence over their original descriptions.

## Remediation pass 1 — unpublished

- **A01 implemented:** service termination in client-before-storage order, 10-second exit waits, explicit force-stop plus a 2-second confirmation wait before proceeding to dependencies, and final VM teardown. If force-stop cannot be confirmed, fall back immediately to VM teardown. Warnings are returned to the console; final teardown failure keeps ownership and prevents the app from quitting silently.
- **A02 implemented at the app ownership boundary:** synchronously reserve lifecycle state, await cancelled startup/restart before stopping, coalesce quit requests, reject stale events by generation, wrap all runtime startup acquisitions in cleanup, cancel listener acquisition, and clean up probes on success, failure, and cancellation. The model uses an injectable runtime; tests deliberately simulate a startup dependency returning after cancellation. Low-level Containerization calls still depend on that library's own completion/timeouts; no new promise of instant cancellation is made.
- **A03 fixed:** byte-framed, bounded UTF-8 log delivery preserves split characters and repairs malformed bytes. Retained diagnostic tails remain readable, callbacks are serialized, and writing after close is rejected.
- **A04 covered defects fixed:** Garage extraction is restricted to its own config block and normalizes CRLF. Image locks are restricted to services, reject duplicate services/image keys/sections, validate full SHA-256 pins and parse image references. This remains the documented platform-specific YAML subset, not a general YAML/Compose engine.
- **A08 fixed:** the selected error headline is capped independently of the log tail.
- **Deferred to pass 2 below:** A05 (OCI manifest/fallback verification), A06 (WebKit readiness/failure recovery), and A07 (disk-space and cache safeguards).

Pass 1 validation was isolated: no production VM, live stack, private volume, or installed bundle was modified. Sandbox entitlements and packaging boundaries were unchanged. Disposable-VM validation followed in pass 2; passing mocks alone do not prove upstream services honor SIGTERM.

Pass 1 finished with **61 passing tests**, with zero known issues or skipped tests. This included 20 additional tests beyond the audit's 41 and converted all nine original defect reproductions to ordinary passing regressions.

## Remediation pass 2 — unpublished

- **A05 fixed:** size/hash-check the resolved manifest before JSON decoding and each YAML layer before interpretation. Fetch each object once, reuse verified fallback bytes, reject ambiguous/missing/duplicate roles, limit objects to 2 MiB and manifests to eight layers. The pinned registry transport independently bounds response buffering. Synthetic transport tests cover corruption and bounds; the disposable diagnostic also verifies the current real public Compose artifact.
- **A06 fixed:** loading/ready/failed states have cancellable generations and a 30-second timeout. Document completion replaces brightness/snapshot retries. Navigation failures and web-content-process termination display a page-only reload path without restarting containers. Tests exercise a real black WebKit page, real failed navigation followed by recovery, simulated process-termination callback, timeout, superseding navigation, and cancellation.
- **A07 implemented:** conservative free-space checks reserve 512 MiB of headroom before image/disk creation. Initfs, new volumes, and replacement rootfs are staged, synchronized, and atomically renamed; rootfs identity stamps follow directory synchronization. Existing disks survive creation failures and cancellation. Manage Storage previews allocated usage and obsolete caches; confirmed cleanup stops the runtime, rechecks candidates, retains shared/referenced image blobs, and never deletes persistent volumes, backups, or service disks. Missing protection metadata retains all image references. A runtime-directory lock excludes concurrent updated app processes during startup or cleanup; legacy prototypes do not honor it.
- The earlier A01/A02 lifecycle fixes are unchanged in scope. The disposable VM verifies actual SIGTERM delivery, clean process exit, a marker written to a shared ext4 volume and read by a second container, then VM teardown. This is not proof that every upstream service flushes correctly and is not a full community-stack startup/migration test.
- A separate development bundle is built and signature-verified with the exact same four sandbox entitlements. The production bundle and running stack remain untouched. Full-stack first-launch testing is intentionally not performed on a host with only about 3.3 GiB free; no production cache cleanup was run to make room.

All eight original findings now have implementations and regression coverage. Remaining release qualification (Developer ID/notarization, quarantined download on another Mac, and full community-stack testing) stays on the release checklist rather than being implied by this local audit.

The final release-configuration suite contains **85 tests**, all passing with **zero known issues or skipped tests**. The complete suite also passed three consecutive repeat runs. A timing assumption exposed by concurrent native UI tests was replaced with a bounded wait for the actual readiness event, rather than increasing a fixed sleep.

Final packaged smoke result: **PASS, process exit 0**. Public artifact verification, VM boot, SIGTERM, clean service exit, shared-volume marker, VM teardown, temporary-runtime removal, and normal application exit all completed. The diagnostic initially exposed a nested-event-loop deadlock when calling AppKit termination directly inside its main-actor task; scheduling that request through the native run loop fixed it and allowed the ordinary asynchronous termination delegate to complete. No production process was signalled.

## Priority findings

### A01 — High: normal shutdown force-kills services

`PrivateOCIStackRuntime.stop()` in `Sources/Studio/Studio.swift` directly calls `LinuxPod.stop()`. In the pinned dependency, `LinuxPod.stop()` calls `process.kill(.kill)` for each running container before unmounting volumes. Quitting the macOS application gracefully therefore does **not** imply graceful shutdown of Redis, Garage, Qdrant, or the platform.

Impact: services cannot finish in-flight requests or perform normal shutdown flushing. Journaled ext4 improves filesystem crash recovery but does not replace application-level shutdown. No data corruption was demonstrated or induced in this audit.

Recommended change: stop accepting new connections, stop the platform before its dependencies, send termination signals with bounded waits, then use pod stop only as the final teardown/fallback. Surface teardown failures instead of silently swallowing every error. Verify ordering with an injectable runtime and a disposable VM fixture, never the user's volumes.

Evidence: application `stop()`; dependency `Sources/Containerization/LinuxPod.swift`, `stop()` and `killContainer(_:signal:)` at version 0.43.0. Code-inspection finding, not a destructive reproduction.

### A02 — High: startup/shutdown ownership is not serialized

`AppModel.start()` checks `.idle` but does not leave it until an asynchronously scheduled task emits a phase event. Two calls in the same main-actor turn can both pass that guard. `restart()` similarly enters `.stopping` inside its task. `shutdown()` cancels the task without awaiting its completion, then calls `runtime.stop()` while `runtime.start()` may be suspended. Swift actors permit interleaving at those suspension points.

Additionally, runtime startup reserves the listener before its `do/catch` cleanup scope begins. Failures while writing Garage configuration, obtaining images, preparing disks, or adding containers bypass that cleanup. The listener remains retained until a later stop/restart. Timed-out health/bridge processes can also bypass their `delete()` calls.

Recommended change: synchronously claim a start/restart state; serialize a single owned lifecycle task; cancel and await startup before teardown; discard stale events using a generation identifier; cover resource acquisition with failure cleanup. Add dependency-injected tests for repeated start, shutdown during every startup stage, failures after listener acquisition, and stale callbacks.

Evidence: `AppModel.start/restart/shutdown`, `PrivateOCIStackRuntime.start`, `startHealthy`, `installHTTPBridge`. Code-inspection finding; no race was induced against the live application.

### A03 — Medium: streaming logs can lose diagnostic text

`MemoryWriter.write` decodes each incoming byte chunk independently as UTF-8. A valid character split across two writes makes either chunk invalid, so otherwise useful text in that chunk is silently omitted from the console. `text()` returns an empty string if one retained byte is invalid; its one-million-byte trimming boundary can itself split a valid character.

Reproductions: `logUnicodeSurvivesEveryByteBoundary`, `invalidLogBytesDoNotHideSubsequentText`, `boundedLogTailRemainsReadableAfterSplittingUnicode`.

Recommended change: frame lines in bytes or use a stateful UTF-8 decoder, retain incomplete sequences across writes, and decode malformed input lossily without discarding surrounding text. Preserve bounded storage and callback ordering.

### A04 — Medium: configuration validation accepts ambiguous input

`GarageConfiguration.extract` searches beyond `garage-config` for any later `content: |`, so it can consume an unrelated config. It also fails to recognize CRLF documents. `OCIComposeLoader.parseImageLock` is not restricted to the `services` block, silently overwrites duplicate service names, and checks only for the substring `@sha256:` rather than a complete valid digest.

Reproductions: Garage scope/CRLF tests and image-lock malformed-digest/duplicate/section tests. Invalid image references may be rejected later by the image library, but that is too late for a reliable, clear preflight error; accepting unrelated valid image entries is also incorrect.

Recommended change: parse a documented strict YAML subset or a proper YAML representation; enforce section boundaries, reject duplicate keys, normalize line endings, validate complete image references, and keep configuration errors free of secret values.

### A05 — Medium: some OCI bytes bypass integrity verification

The loader verifies YAML layers in its first pass, but fallback identification re-fetches layer 0/1 without verifying the new bytes. It fetches the manifest with the dependency's JSON `fetch` method; inspection of `RegistryClient+Fetch.swift` shows that this method decodes a response but does not compare its bytes against the descriptor hash. The UI nevertheless logs “Verified OCI manifest”.

Recommended change: fetch each object once, validate size/hash before decoding, reuse the verified YAML bytes for fallback selection, and impose sensible artifact-size/layer-count limits before buffering. Add fake-registry transport tests for changed fallback responses, corrupt manifests, missing/ambiguous layers, and excessive payloads. Existing unit tests only verify the local hash-checking helper, not network orchestration.

### A06 — Medium: WebKit failure and readiness recovery are incomplete

The navigation coordinator handles successful navigation but has no navigation-failure or web-content-process-termination callbacks. An initial load failure can leave the startup overlay indefinitely. The first-paint heuristic regards near-black samples as not visible and retries whole-page snapshots for up to about 18 seconds; a valid dark page can trigger those retries. Snapshot retries are not tracked/cancelled on dismantling or superseding navigation.

Recommended change: model loading/ready/failed separately from container health; show retryable WebKit errors, handle content-process termination, and cancel old readiness work by navigation generation. Replace brightness-based readiness with a bounded document/render signal. Add isolated dark-page, failed-navigation, crash-recovery, and teardown tests.

### A07 — Medium: disk growth has no proactive guardrail

Studio has no free-space preflight, storage-usage view, or retention policy for obsolete image/artifact cache entries. New image versions accumulate in the image store. Rootfs replacement removes the previous service disk before the new unpack is known to succeed. Writable persistent volumes are intentionally retained, and must not be treated as disposable cache.

During this audit, the host reported roughly 4.7 GiB available. This is a current capacity warning, **not** proof Studio accounts for all missing space; no disk-usage attribution or deletion was performed.

Recommended change: estimate required temporary/unpack capacity, fail early with actionable details, stage replacement rootfs and atomically promote on success, and offer a previewable cleanup restricted to unreferenced caches. Never delete persistent volumes without separate explicit consent.

### A08 — Low: failure summaries are not fully bounded

`StartupFailure.message` bounds the appended log tail but prepends the selected error line without bounding it. A single huge line therefore creates a huge UI error string despite the tail limit.

Reproduction: `startupSummaryHasBoundedSizeForOneHugeLine`. Recommended change: bound the headline separately and keep full available detail in the console.

## Security and packaging checks

- The installed local bundle passes strict code-signature verification and hardened-runtime verification.
- Its actual signed entitlements are exactly `com.apple.security.app-sandbox`, `com.apple.security.network.client`, `com.apple.security.network.server`, and `com.apple.security.virtualization`, all enabled. No permission expansion was made.
- The inspected executable is arm64 and links only Apple/system libraries. Containerization is linked into the main sandboxed process; there are no bundled macOS helper executables. The bundled Linux kernel runs inside the VM.
- The local TCP listener explicitly binds `127.0.0.1`, not all network interfaces. Runtime images/volumes remain in the app's private container.
- `_blank` handoff allows only HTTP(S) GET URLs and rejects local files, custom schemes, and POST handoff. Tests inject a fake opener, so no external browser is opened by those tests.
- Shell syntax checks pass for all packaging scripts. CI/release workflows already run the complete Swift test suite, so added tests need no workflow change.
- The inspector uses guarded private selectors and the window drag surface depends on AppKit view hierarchy details. These remain OS-compatibility risks; the guards do not turn private APIs into supported public APIs.
- This is not a penetration test. Sandbox denial probes, runtime egress filtering, dependency vulnerability scanning, live VM fault injection, and notarization were not performed in this pass.

## Test policy

Original audit result: added 32 tests, bringing the suite from 9 to 41. The first unwrapped run reproduced 9 failing tests. The audit-only run used explicit known-issue wrappers. In remediation pass 1, all nine wrappers were removed after implementing fixes; lifecycle and cleanup regressions were added as ordinary tests too.

Unit/integration tests use in-memory buffers, fake browser opening, isolated nonpersistent WebKit views, synthetic configuration, and uniquely named temporary storage. They never open the production runtime or start Linux VMs. The separately invoked packaged smoke test starts only its own disposable VM under a diagnostic bundle identity.

Functional tests cover operator semantics and laziness, secret-safe errors, listener completion ordering/concurrency, byte-size and hash rejection, log limits/flush/Unicode recovery, console source switching/retention/selection, browser handoff, serialized lifecycle ownership, shutdown ordering/fallback, teardown retry, and probe cleanup. No tests are skipped or wrapped as known failures in the current suite.
